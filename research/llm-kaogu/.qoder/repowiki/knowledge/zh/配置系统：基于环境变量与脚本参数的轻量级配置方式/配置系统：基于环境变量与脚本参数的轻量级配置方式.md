本仓库未实现统一的配置框架，而是采用分散、轻量的配置方式，主要依赖以下两种机制：

1. **环境变量（Secrets）**：百度 OCR 接口凭据通过 `os.environ` 读取，要求设置 `BAIDU_OCR_API_KEY` 和 `BAIDU_OCR_SECRET_KEY` 两个环境变量。这是当前唯一涉及敏感配置的方式。
2. **命令行参数**：训练脚本 `scripts/train_classifier.py` 使用 `argparse` 暴露 `--epochs`、`--lr`、`--batch-size` 等超参，作为运行时可调的配置入口。
3. **硬编码路径**：数据集根目录 `DATA_DIR` 在脚本中通过相对路径 `Path(__file__).parent.parent / "datasets" / "ArchaeoMind_dataset"` 硬编码，未提供外部覆盖机制。
4. **项目元配置**：顶层 `pyproject.toml` 仅声明包名、版本与 Python 版本约束，不包含应用运行期配置项；`main.py` 为占位入口，无实际加载逻辑。

此外，根目录下存在 `datasets/archaeoscape/configs/` 空目录结构（含 callbacks/、data/、model/、trainer/ 等子目录），但当前未被任何代码引用，属于遗留或未完成迁移的 Hydra 风格配置骨架，对实际运行无影响。

**开发者应遵循的规则**：
- 新增 API 密钥一律通过 `os.environ` 注入，禁止写死在源码中。
- 可调节的训练超参优先通过 `argparse` 暴露，保持脚本自文档化。
- 数据路径如需变更，应在脚本内集中修改 `DATA_DIR` 常量，避免散落多处。
- 暂勿引入配置文件（YAML/TOML）——当前规模下环境变量 + CLI 参数已足够，避免过度工程化。
